## Цель

Пользователь отмечает элементы формы 1С текстовыми комментариями в открытом
превью и управляет ими в отдельном списке. AI-агент получает комментарии через
MCP и понимает, к каким элементам они относятся.

## Требования

### Требование 1.1: Добавление аннотации

Пользователь может выбрать видимый элемент управляемой формы и добавить к нему
непустой текстовый комментарий во встроенном поле ввода рядом с выбранным
элементом. Ввод можно отменить без создания аннотации.

Критерий проверки: после подтверждения комментарий связан с именем и ID
выбранного элемента формы; отмена и пустой ввод не создают запись. Системный
диалог `window.prompt()` не открывается.

### Требование 1.2: Отображение

На форме аннотация обозначается компактной номерной меткой без текста и стрелки.
Отдельный сворачиваемый список в нижнем правом углу превью показывает общее
количество аннотаций и для каждой — тот же номер, название элемента и полный
текст. Список включает аннотации всех вкладок текущей формы. Текст отображается
буквально, без интерпретации HTML.

Критерий проверки: номер метки соответствует строке списка; открытый список
можно свернуть до заголовка со счётчиком; содержимое списка и поле ввода не
меняют разметку формы; HTML в тексте не исполняется.

### Требование 1.3: Получение через MCP

AI-агент может получить аннотации конкретного `preview_id`. Для каждой
аннотации возвращаются её ID, имя и ID элемента формы и текст комментария.

Критерий проверки: MCP возвращает аннотации только запрошенного превью, и их
можно сопоставить с элементами результата `inspect`.

### Требование 1.4: Редактирование и удаление

Пользователь может изменить текст аннотации или удалить её в списке. Правка
меняет только текст: ID аннотации и привязка к элементу сохраняются. Пустой
текст не сохраняется. Удалённая аннотация перестаёт отображаться и
возвращаться через MCP. Если сохранить правку не удалось, прежняя аннотация
остаётся без изменений, введённый текст остаётся в поле редактора, а
пользователь видит сообщение об ошибке.

Критерий проверки: после сохранения правки список и ответ MCP содержат новый
текст при прежних ID; отмена правки сохраняет старый текст; после удаления
аннотации нет ни в превью, ни в ответе MCP. Номера оставшихся меток и строк
списка совпадают.
При ошибке сохранения список и MCP сохраняют прежний текст, а редактор —
введённый текст до повторной попытки или отмены.

### Требование 1.5: Только текущая сессия

Аннотации хранятся только в памяти процесса MCP и не записываются на диск.
Закрытие превью удаляет его аннотации, а перезапуск сервера удаляет все
аннотации. Повторный `open_preview` того же файла очищает аннотации, сохраняя
`preview_id` и URL этого превью.

Критерий проверки: после повторного открытия список пуст, а `preview_id` и URL
не изменились; после закрытия превью аннотации недоступны, а дерево и
содержимое исходников 1С не изменились.

### Требование 1.6: Сохранение привязки при навигации

При переключении вкладок формы аннотации остаются привязанными к своим
элементам. Метки видны только у элементов текущей вкладки и появляются вновь,
когда элементы становятся видимыми; список сохраняет аннотации всех вкладок.
Несколько комментариев к одному элементу не заменяют друг друга. Выбор строки
списка не переключает вкладку и не выполняет переход к элементу.

Критерий проверки: переключение на другую вкладку и обратно восстанавливает
все номерные метки у правильных элементов без изменения макета формы; список
остаётся доступным, а действия в нём не меняют активную вкладку.

### Требование 1.7: Независимость обычного превью

Аннотации не должны мешать загрузке и навигации обычного превью.

Критерий проверки: превью без аннотаций загружается, а переключение вкладок и
обычная навигация работают.

## Ограничения

- Первая версия поддерживает только управляемые формы.
- Аннотация привязывается к целому элементу формы, не к произвольной области
  экрана.
- Список и поле ввода не меняют DOM формы и её размеры. Подключение аннотаций
  не требует изменений `1c-preview-core`.
- Существующие операции просмотра, навигации, снимков и правки формы не должны
  менять поведение.
- MCP расширяется совместимо: существующие инструменты и ответы не ломаются.

## Не входит в scope

- Постоянное хранение и история аннотаций.
- Совместная работа нескольких пользователей или синхронизация аннотаций между
  несколькими одновременно открытыми браузерными вкладками одной сессии.
- Автоматическое изменение формы по аннотации без отдельной команды
  пользователя агенту.
- Переход к элементу по нажатию на строку списка, выбор вложенной части
  элемента и экспорт аннотаций в сообщение Orca.
- Аннотирование макетов и MXL.

## Решения и открытые вопросы

- Согласован ориентир интерфейса Orca: встроенный ввод, номерные метки и
  отдельный список с редактированием и удалением. Выбор строки списка не
  выполняет навигацию. Список располагается поверх нижнего правого угла
  превью и сворачивается; в раскрытом виде он может закрывать часть формы.
