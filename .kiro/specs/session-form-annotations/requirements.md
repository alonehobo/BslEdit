## Цель

Пользователь отмечает элементы формы 1С текстовыми комментариями прямо в
открытом превью, а AI-агент получает эти комментарии через MCP и понимает, к
каким элементам они относятся.

## Требования

### Требование 1.1: Добавление аннотации

Пользователь может выбрать видимый элемент управляемой формы и добавить к нему
непустой текстовый комментарий.

Критерий проверки: после ввода комментария он связан с именем и ID выбранного
элемента формы.

### Требование 1.2: Отображение

Аннотация показывается рядом с выбранным элементом в виде подписи с указателем.
Текст отображается буквально, без интерпретации HTML.

Критерий проверки: пользователь видит подпись у нужного элемента, а HTML в
тексте не исполняется.

### Требование 1.3: Получение через MCP

AI-агент может получить аннотации конкретного `preview_id`. Для каждой
аннотации возвращаются её ID, имя и ID элемента формы и текст комментария.

Критерий проверки: MCP возвращает аннотации только запрошенного превью, и их
можно сопоставить с элементами результата `inspect`.

### Требование 1.4: Удаление

Пользователь может удалить аннотацию. После удаления она перестаёт
отображаться и возвращаться через MCP.

Критерий проверки: удалённой аннотации нет ни в превью, ни в ответе MCP.

### Требование 1.5: Только текущая сессия

Аннотации хранятся только в памяти процесса MCP и не записываются на диск.
Закрытие превью удаляет его аннотации, а перезапуск сервера удаляет все
аннотации.

Критерий проверки: после закрытия превью аннотации недоступны, а дерево и
содержимое исходников 1С не изменились.

## Ограничения

- Первая версия поддерживает только управляемые формы.
- Аннотация привязывается к целому элементу формы, не к произвольной области
  экрана.
- Существующие операции просмотра, навигации, снимков и правки формы не должны
  менять поведение.
- MCP расширяется совместимо: существующие инструменты и ответы не ломаются.

## Не входит в scope

- Постоянное хранение и история аннотаций.
- Совместная работа нескольких пользователей.
- Автоматическое изменение формы по аннотации без отдельной команды
  пользователя агенту.
- Аннотирование макетов и MXL.

## Решения и открытые вопросы

- Аннотации непостоянны и не записываются в исходники 1С.
- Обновляемость локальной доработки относительно upstream будет описана в
  архитектурном дизайне, а не в продуктовом контракте.
- Открытых вопросов, блокирующих дизайн, нет.
