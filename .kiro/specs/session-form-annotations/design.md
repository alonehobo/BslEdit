## Краткое решение

<a id="implementation"></a>

Аннотации хранятся в существующем `PreviewServer::Session` отдельно для каждого
`preview_id`. Это обеспечивает изоляцию нескольких одновременно открытых форм
и позволяет MCP видеть аннотации, созданные в пользовательском окне.

Отдельный модуль `session-annotations.js` управляет кнопкой режима, встроенным полем
ввода, номерными метками и сворачиваемым списком поверх нижнего правого угла превью.
Список содержит аннотации всех вкладок; строка не вызывает навигацию. Из списка
можно изменить текст или удалить запись. Все пользовательские строки выводятся
через `textContent`, поэтому HTML не исполняется.

`agent-viewer.js` передаёт модулю контейнеры `#preview` и
`#agent-preview-pane`, функцию поиска имени и заголовка элемента по ID, а при
загрузке снимка — список, ревизию и признак доступности. После перерисовки или
переключения вкладки он вызывает пересчёт положения меток. Модуль сам
обрабатывает ввод, клики и HTTP-запросы к сессии. Он не меняет DOM формы,
не использует API рендерера и не знает о MCP.

MCP получает список через совместимое расширение существующего инструмента
`preview`: новая операция `annotations`. Она читает массив из выбранной сессии.
Отдельный инструмент и отдельный класс хранилища не нужны. Результат операции:

```json
{
  "annotations": [
    {
      "id": "a1",
      "elementId": "983",
      "elementName": "ОтборГоловнойКонтрагент",
      "text": "Пояснить назначение"
    }
  ]
}
```

## Трассировка требований

| Требование | Решение или компонент |
|---|---|
| 1.1 | Режим и встроенный ввод в `session-annotations.js`; массив в `PreviewServer::Session` |
| 1.2 | Номерные метки и список вне DOM формы; оформление в `session-annotations.css` |
| 1.3 | `preview(operation="annotations")` и команда страницы `annotations` |
| 1.4 | Редактирование и удаление в списке; PATCH и DELETE записи в сессии |
| 1.5 | Состояние только в памяти `PreviewServer::Session`; очистка при повторном открытии и reload |
| 1.6 | Привязка меток по `elementId` после перерисовки вкладки; список не вызывает переход |
| 1.7 | Аннотации как необязательная возможность native-превью; загрузка документа от них не зависит |

## Boundary и зависимости

| Компонент | Ответственность | Разрешённые зависимости |
|---|---|---|
| `agent-viewer.js` | Передать контейнеры, функцию поиска элемента и снимок; вызвать пересчёт меток при изменении формы | Только интерфейс `session-annotations.js` |
| `session-annotations.js` / `.css` | Ввод, метки, список, правка и удаление; DOM и HTTP-запросы аннотаций | Контейнер превью, `data-id` элементов, сведения об элементе по ID и HTTP-адрес своей native-сессии |
| `PreviewServer::Session` / MCP dispatch | Хранение по `preview_id`, HTTP-мутации и чтение `annotations` | Существующая сессия превью |

Рендереры из `1c-preview-core`, Node-сервер, загрузчик файлов и `Form.xml` не
знают об аннотациях и не меняются. Общая страница использует возможность
аннотирования только когда она явно предоставлена native-сессией.

## Контракт и жизненный цикл

<a id="lifecycle"></a>

- Операция `annotations` только читает состояние. Атрибут `readOnlyHint`
  относится ко всему существующему инструменту `preview`, а не к отдельной
  операции.
- `id` генерируется простым счётчиком серверной сессии (`a1`, `a2`, ...).
- `elementName` берётся из outline, `elementId` — из стабильного ID элемента
  текущей формы.
- Native `state.json` включает массив `annotations` в тот же снимок, что и
  документ. Отсутствие поля в ответе Node-сервера означает, что аннотирование
  недоступно; загрузка документа не зависит от отдельного запроса аннотаций.
- Страница добавляет запись через POST `annotations`, изменяет её текст через
  PATCH `annotations/{id}` с телом `{revision,text}` и удаляет через DELETE
  `annotations/{id}`. PATCH возвращает запись с прежними `id`, `elementId` и
  `elementName`; пустой после `trim()` текст отклоняется. MCP читает тот же
  массив непосредственно по `preview_id`.
- Закрытие превью удаляет его `Session` вместе с аннотациями. Перезапуск процесса
  удаляет все сессии. Файловых операций нет.
- При повторном `open_preview` того же файла сервер очищает аннотации и
  увеличивает ревизию, сохраняя `preview_id` и URL. `reload` также очищает
  аннотации; новый снимок убирает прежние метки и строки со страницы.
- POST, PATCH и DELETE передают ревизию снимка, из которого пользователь увидел
  аннотации. Сервер проверяет её вместе с изменением списка под блокировкой
  сессии и возвращает HTTP 409 при несовпадении. Ответ на старый запрос,
  пришедший после загрузки нового снимка, страница не применяет локально.
- При ошибке PATCH редактор остаётся открыт с введённым текстом и сообщает
  об ошибке; список не меняется. Отмена редактора оставляет исходную запись.
- При перекрытии загрузок разных ревизий страница применяет результат только
  последней начатой загрузки. Команда `select` обновляет положение меток после
  перехода к элементу другой вкладки.
- Метки находятся вне DOM формы и хранят `elementId`, а не постоянную ссылку
  на DOM-узел. Метка создаётся и для элемента пока неактивной вкладки,
  остаётся скрытой без узла и при переключении находит актуальный узел по ID:
  рендерер может заменить узлы вкладки.
- Список всегда содержит все записи текущего превью. Номера вычисляются из
  порядка массива при отображении и после удаления пересчитываются; они не
  входят в сессионный и MCP-контракт. Раскрытая панель может закрывать часть
  формы, но не изменяет размеры превью; заголовок со счётчиком сворачивает её.

## Обновление клона из upstream

Доработка ведётся в отдельной ветке. Обновление клона выполняется через rebase
этой ветки на новый `origin/main`, после чего запускаются тесты пакета
`1c-form-viewer`.

## Проверки

- Целевой сценарий нескольких превью в `native-contract.test.ts` — MCP-контракт,
  правка текста и независимость сессий.
- `annotations.e2e.test.ts` — Node-превью без аннотаций, вкладки, список и
  защита от запоздалых ответов. Сценарий аннотаций в `browser.e2e.test.ts` —
  создание, буквальный HTML, редактирование и удаление.
- `npm test --workspace=1c-form-viewer` — полный регрессионный набор; его
  результат сообщается отдельно от целевых проверок.
- Проверка `git diff` подтверждает отсутствие изменений файлов проекта 1С;
  установленный native-комплект проверяется отдельно.

## Риски

- Раскрытый список может закрывать нижний правый участок формы. Его можно
  свернуть до заголовка; размер самой формы при этом не меняется.
- `reload` очищает несохранённые аннотации; это ожидаемое поведение сессионного
  инструмента.
- Другая браузерная вкладка той же сессии не увидит добавление или удаление
  сразу; совместная работа не входит в требования.
- `capture_preview` захватывает `#preview`, а метки и список находятся вне
  него. Текст доступен агенту через операцию `annotations`, но в снимок не
  входит.
- Если ресурс `session-annotations.js` не загрузится, безусловное создание
  модуля остановит общую страницу. Штатная сборка проверяет наличие ресурса.
- Изменения upstream в `agent-viewer.js` или MCP-схеме могут дать конфликт
  rebase; малое число интеграционных точек и тесты делают его явным.

## Отклонённые альтернативы

- Файловое или профильное хранилище: не требуется для сессионного общения и
  нарушает ограничение «не записывать на диск».
- Отдельный `AnnotationStore` в C++: для массива внутри уже существующей
  `PreviewServer::Session` не нужен.
- Новый MCP-инструмент: увеличивает публичную поверхность; операция логически
  относится к уже открытому превью и помещается в `preview`.
- Встраивание аннотаций в рендерер формы: сильнее связывает функцию с развитием
  `1c-preview-core` и повышает вероятность конфликтов с upstream.
