## Краткое решение

<a id="implementation"></a>

Аннотации хранятся в существующем `PreviewServer::Session` отдельно для каждого
`preview_id`. Это обеспечивает изоляцию нескольких одновременно открытых форм
и позволяет MCP видеть аннотации, созданные в пользовательском окне.

В пользовательском режиме заголовок получает кнопку «Аннотация». После её
включения щелчок по элементу формы запрашивает текст, передаёт запись серверной
сессии и добавляет подпись с указателем. У подписи есть кнопка удаления, которая
удаляет ту же запись из сессии. Текст назначается через `textContent`, поэтому
HTML не исполняется.

MCP получает список через совместимое расширение существующего инструмента
`preview`: новая операция `annotations`. Она читает массив из выбранной сессии.
Отдельный инструмент и отдельный класс хранилища не нужны. Результат операции:

```json
{
  "annotations": [
    {
      "id": "a1",
      "elementId": "983",
      "elementName": "ОтборГоловнойКонтрагент",
      "text": "Пояснить назначение"
    }
  ]
}
```

`neat-annotations` используется как полная локальная копия CSS под лицензией
MIT: визуальная выразительность библиотеки является частью выбранного решения.
Состояние и MCP-ответ при этом не зависят от её CSS-классов.

## Трассировка требований

| Требование | Решение или компонент |
|---|---|
| 1.1 | Режим аннотирования в `agent-viewer.js` и массив в `PreviewServer::Session` |
| 1.2 | Локальный CSS `neat-annotations.css` и безопасный DOM-рендер подписи |
| 1.3 | `preview(operation="annotations")` и команда страницы `annotations` |
| 1.4 | Кнопка удаления у подписи и удаление записи из серверной сессии |
| 1.5 | Состояние только в памяти `PreviewServer::Session` |

## Boundary и зависимости

| Компонент | Ответственность | Разрешённые зависимости |
|---|---|---|
| `agent-viewer.js` | Ввод, отображение и удаление аннотаций | Текущий DOM, outline формы и HTTP-интерфейс своей сессии |
| `neat-annotations.css` | Только стрелка и визуальное оформление | CSS, без JavaScript и состояния |
| `PreviewServer::Session` / MCP dispatch | Хранение по `preview_id` и выдача операции `annotations` | Существующая сессия превью |

Рендереры из `1c-preview-core`, загрузчик файлов и `Form.xml` не знают об
аннотациях и не меняются.

## Контракт и жизненный цикл

- Операция `annotations` только читает состояние и имеет `readOnlyHint` в
  составе существующего инструмента `preview`.
- `id` генерируется простым счётчиком серверной сессии (`a1`, `a2`, ...).
- `elementName` берётся из outline, `elementId` — из стабильного ID элемента
  текущей формы.
- Страница добавляет и удаляет записи через HTTP-адрес своей сессии; MCP читает
  тот же массив непосредственно по `preview_id`.
- Закрытие превью удаляет его `Session` вместе с аннотациями. Перезапуск процесса
  удаляет все сессии. Файловых операций нет.
- При `reload` сервер очищает аннотации этой сессии, а страница убирает подписи.

## Обновление клона из upstream

Доработка ведётся в отдельной ветке. Обновление клона выполняется через rebase
этой ветки на новый `origin/main`, после чего запускаются тесты пакета
`1c-form-viewer`.

## Проверки

- `npm run test:unit --workspace=1c-form-viewer` — схема MCP, маршрутизация и
  независимость превью.
- `npm run test:e2e --workspace=1c-form-viewer` — создание, буквальный HTML,
  чтение и удаление аннотации в браузере.
- `npm test --workspace=1c-form-viewer` — полный пакетный regression gate.
- Проверка `git diff` подтверждает отсутствие изменений вне репозитория
  BslEdit и любых файлов проекта 1С.

## Риски

- Подпись может перекрывать соседние элементы. Первая версия использует
  фиксированное направление и существующие CSS-переменные; ручное перемещение
  не добавляется.
- `reload` очищает несохранённые аннотации; это ожидаемое поведение сессионного
  инструмента.
- Изменения upstream в `agent-viewer.js` или MCP-схеме могут дать конфликт
  rebase; малое число интеграционных точек и тесты делают его явным.

## Отклонённые альтернативы

- Файловое или профильное хранилище: не требуется для сессионного общения и
  нарушает ограничение «не записывать на диск».
- Отдельный `AnnotationStore` в C++: для массива внутри уже существующей
  `PreviewServer::Session` не нужен.
- Новый MCP-инструмент: увеличивает публичную поверхность; операция логически
  относится к уже открытому превью и помещается в `preview`.
- Встраивание аннотаций в рендерер формы: сильнее связывает функцию с развитием
  `1c-preview-core` и повышает вероятность конфликтов с upstream.
